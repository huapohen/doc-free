## 人可见的日历操作

- 全天日程在单独的全天栏显示，与按小时排列的日程分开。手机的时间页有开始、结束和全天开关；全天只显示日期滚轮，切回定时保留原来的时刻草稿。
- 重复支持每天、每周、每个工作日、每月日期、每月第几个星期几、每年和自定义间隔。支持截止日期、有限次数和永不截止；手机保留独立的截止入口。
- 周、日、三日、月视图向服务端查询当前窗口，按实际实例呈现；同一系列可以同时出现多次，不能按主日程 ID 把实例合并掉。
- 编辑、取消和参与意向对重复日程明确选择“仅本次”或“整个系列”。一位 Agent 的接受状态与人类一样显示在参与者列表中。
- 主题、地点等普通修改保留原来的精确时刻；跨夏令时的历史日程不能因为重开表单就无意移动一小时。

## Agent 原生协议与持久化

人类界面和 Agent 的 HTTP、MCP、A2A 与 Python SDK 共用同一日历模型、权限与服务端 reducer。Agent 可以直接创建、读取、修改、取消及回应系列或实例，无需通过鼠标录制这些动作。

全天以 `start_date` 和排他的 `end_date` 为权威值。例如界面显示 9 月 8 日全天，协议写入 `start_date=2026-09-08`、`end_date=2026-09-09`。定时日程使用带时区的时刻，IANA 时区参与重复规则展开。旧普通日程保留兼容路径。

`GET /api/im/calendar` 返回主系列；`GET /api/im/calendar/occurrences` 返回可见窗口中的实例。每个实例保留稳定的原始锚点、`occurrence_id`、系列版本和规则代次。有限窗口最多 366 天，单页最多 500 个实例；分页游标绑定身份、窗口和可见系列版本，变更后旧游标失效。不会把无限重复预先复制成无限文件或记录。

新原生工具包含 `office_calendar_occurrences` 与 `office_cancel_event`，其余日历工具扩展全天、时区、规则、作用范围、版本和幂等请求字段。Python SDK 传递服务端回执，不在客户端独立展开规则或静默重试。

修改用主系列版本 CAS；断网后的同意图重试返回原回执。重试仍验证当前调用者权限和原请求一致性。已成功创建后，另一受邀人离群不能阻断原请求回执恢复；新创建仍禁止邀请已离群成员。移动单次实例会清除该实例原有参与意向，保留其他实例；结构性改系列有例外时需显式重置例外。

服务端使用 Temporal，客户端使用 IANA timezone 数据。不存在的当地时间跳过；重复的当地时间采用早偏移；每月不存在的日期和非闰年的 2 月 29 日跳过。更新历史未变化的时刻保留原始精度与偏移。

## 尚未完成

全量飞书页面和功能还没有逐项完成，不能把本阶段称为全量或像素完全一致。日历“本次及以后”、多个每月日期组合、完整会议室资源、农历、提醒/忙闲等仍有缺口。视频会议关联的全天或重复预约尚未支持，界面和协议明确限制，不伪造成功。

本阶段只在 macOS 和 iPhone 17 模拟器原生验收，Windows、Android、Web 未重新构建验收。云录制、转写、生产签名公证及可靠的全量自主工作还有后续工作。

控制期间的系统级人工键盘重复输入根因仍未确认，本阶段没有做人体键盘复现，不能宣称已修复；上阶段已验证的模拟器中文输入不等于解决系统双写。阶段结束停止本次鼠标键盘操作，保留服务和两端应用供用户验收。这并不等于已经定位或修复系统输入链路。
